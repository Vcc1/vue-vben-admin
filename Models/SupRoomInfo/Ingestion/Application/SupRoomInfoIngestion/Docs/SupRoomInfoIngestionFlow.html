SupRoomInfoIngestion 程序过程与数据流转图

这个页面描述当前 SupRoomInfoIngestion Worker 的核心执行流程：从 Redis 两类来源读取新房型，写入内存队列，批量标准化后落库，再执行存储过程同步正式表。

Worker: SupRoomInfoIngestionWorker Producer / Consumer List 直连查价来源 Set 缓存查价来源 批量写 TempSupRoomInfo2

1. 总体流程图

入口宿主 SupRoomInfoIngestionWorker 会同时启动 Producer 和 Consumer；Producer 结束后关闭 Channel，再由 Consumer 完成剩余批次处理。

2. 状态与监控

  • SupRoomInfoIngestionState 维护五个核心值：QueueRemaining、InProgress、Completed、ListPending、SetPending。
  • SupRoomInfoIngestionMetricsWorker 每隔 MetricsLogIntervalSeconds 秒记录一次当前状态。
  • SupRoomInfoIngestionMetrics 会记录 source fetch、pipeline step、error、duration、batch size 等指标。

3. 数据对象流转

List / Set 原始数据

来源描述
Redis List直连查价发现的新房型，逐条 Pop。
Redis Set缓存查价发现的新房型，按供应商 Key Pop 多条。
JSON反序列化后映射为 TempSupRoomInfo2。

内存统一对象

对象用途
TempSupRoomInfo2全流程统一载体，进入 Channel、标准化、批量入库都使用它。
字段示例SupId、SHotelCode、SRoomCode、SRoomNameCN、SRoomNameEN、BedInfo、BedInfoKey、AcreageFrom/To。

数据库侧

目标动作
TempSupRoomInfo2批量导入临时表。
正式表通过存储过程 SyncSupRoomInfoFromTemp2 同步。
临时表清理同步后执行 TRUNCATE TABLE TempSupRoomInfo2。

5. 关键配置

  • FetchBatchSize：每轮从来源最多抓取多少条。
  • WriteBatchSize：Consumer 每次攒满多少条再批量落库。
  • IdleDelaySeconds：当没有数据时 Producer 的等待时间。
  • ListKey：直连查价新房型队列 Key，默认 NewSupRoom。
  • SetKeyPrefix：缓存查价新房型 Key 前缀，当前代码中为 nr_。
  • SetSupIds：需要轮询的供应商集合。
